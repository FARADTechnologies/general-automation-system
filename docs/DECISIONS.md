# Decisions

One line per reversible decision. Newest at the bottom.

- 2026-11-08 Repository keeps its name `general-automation-system`; renaming gives no benefit now.
- 2026-11-08 Designer deliveries imported from the original zips into `import/design-with-dashboard` and `import/design-app-only`; dependencies, build output and single-file bundles left out (rebuildable with `npm run build:single`).
- 2026-11-08 The designer's own tooling folder and two capture scripts with local machine paths are not imported; they are tooling, not product.
- 2026-11-08 Base for `apps/web` is the Caspia app (identical in both deliveries); the dashboard delivery contributes only selected console panels, rebuilt on real data.
- 2026-11-08 Frontend stays React 18 + Vite 5 + react-router 6 (designer's stack). New code is TypeScript; designer JSX is converted file by file only when touched.
- 2026-11-08 Stable element IDs reuse the designer's existing `data-nav-id` attribute instead of introducing a second attribute.
- 2026-11-08 The browser-side mock bank (`bank/api.js`, localStorage state) is replaced by Core Bank + Bridge; the client keeps no business logic.
- 2026-11-08 `MemoryRouter` is replaced by a browser router under `/app`, driven by hub UI state, so deep links and mirroring work.
- 2026-11-08 Seed data is rebuilt server-side to match the brief (cards 4417/9026/7731, brief contact list, 90 days, injection memo, canaries); designer seed is not reused.
- 2026-11-08 Landing page and the dashboard's "AI Studio", "Money Coach", "Versions", login and "planned" pages are dropped from the product (see `docs/AUDIT.md`).
- 2026-11-08 Working product name stays "Seda" (designer's) until the captain decides otherwise; bank brand stays "Caspia".
- 2026-11-08 Development guide lives in `CONTRIBUTING.md`.
- 2026-11-08 Package manager is pnpm via corepack (workspace monorepo).
- 2026-11-08 Services use Express 5 and run TypeScript directly with tsx; no build step for backends.
- 2026-11-08 Bridge audit log uses Node's built-in `node:sqlite` with triggers that reject UPDATE/DELETE; no native modules.
- 2026-11-08 Core Bank keeps state in memory, one seeded customer per demo session; reset reseeds.
- 2026-11-08 MCP runs stateless (one server per request, JSON responses); the agent re-lists tools when the Bridge signals a change.
- 2026-11-08 MCP tool names are capability IDs with dots replaced by underscores, because the model API rejects dots in tool names.
- 2026-11-08 Confirmation needs an httpOnly device cookie issued to the phone by the Bridge; the agent never holds it. Production would use delegated tokens / CIBA.
- 2026-11-08 Bridge notifies the agent of confirmation outcomes through an HMAC-signed webhook.
- 2026-11-08 Policy limits are re-checked at commit time, not only at prepare time.
- 2026-11-08 Merchant names, counterparties and memos are returned under `untrusted_text` in tool output.
- 2026-11-08 Runtime model `claude-sonnet-5-5`, effort `medium`, thinking `between_tools` (lowest setting; `disabled` is rejected on this model). To be re-chosen from eval data in M6.
- 2026-11-08 Correction to the brief: Sonnet 5.5 cache reads cost $0.20/MTok, not $0.10. Haiku 5.5 input $0.10, output $0.50 as stated.
- 2026-11-08 Server-side refusal fallback (`fallbacks: "default"`) is on; it only re-routes safety declines and can be turned off with `AGENT_FALLBACK=0`.
- 2026-11-08 Tools are sent with `strict: true`; JSON-schema keywords the API cannot enforce (min/max, lengths) are stripped from the model copy and still enforced by the agent guard and the Bridge.
- 2026-11-08 The task ledger is appended as a mid-conversation `system` message, so the history stays append-only and the prompt cache stays valid.
- 2026-11-08 After a prepare, the agent loop waits inside the tool call for the customer's decision and returns the Bridge-verified outcome as the tool result; the model never sees a pending action as done.
- 2026-11-08 A state-changing call requires one of the capability's `intent_terms` in the user's own words for the current task (blocks injection-driven actions).
- 2026-11-08 Contact search prefers exact name-word matches, then word prefixes, so "Ali" does not return "Aliyeva".
- 2026-11-08 `apps/web` ports the designer's Caspia screens; a compatibility store keeps their `useStore()` API, with accounts, cards, contacts, transactions, bills and templates live from the bank and other products as static demo content.
- 2026-11-08 The lock screen is off in the demo so judges land on the home screen; the bank confirmation keeps its own (mocked) biometric/PIN step.
- 2026-11-08 Manual money actions in the designer screens show an honest message pointing to the assistant; the contact-transfer form's Continue sends the typed request through the assistant.
- 2026-11-08 Runtime-owned screens live in `apps/web/src/app/core-screens/`, outside the designer's paths, so the two never edit the same files.
- 2026-11-08 The stage reads a read-only, masked "bank view" of its own session from the Bridge to show what the bank received.
- 2026-11-08 Dev gateway is Vite's proxy; production uses a small gateway with the same routes (M4).
- 2026-11-08 Production runs one container: a launcher starts Core Bank, Bridge, Agent and a gateway as separate processes, each with only its own environment (the agent never gets the Core Bank URL or key). Internal keys are generated per boot unless set.
- 2026-11-08 The gateway exposes only the web client, /api/agent, /ws, /bridge/* (confirmation) and /app-api/*; Core Bank internals and the Bridge's MCP and admin routes are not reachable from outside.
- 2026-11-08 Early phone tests use a Cloudflare quick tunnel (HTTPS + WebSocket, no account). It depends on this laptop and is not the final hosting.
- 2026-11-08 ANTHROPIC_API_KEY is stored as a GitHub Actions secret for CI and deploys.
- 2026-11-08 Designer branches merged after review; the designer's /transfers/contact, /subscriptions, /bills, /invest and stage panels replace the runtime's placeholder versions. The bank app backend serves display-ready analytics, branches and simulated investment resources so the screens hold no arithmetic.
- 2026-11-09 Anthropic API credit ran out; a Gemini adapter (`AGENT_PROVIDER=gemini`) sits behind the same model interface. Guards, Bridge and confirmation are unchanged, so the invariants hold for either model.
- 2026-11-09 Gemini free tier allows 20 requests per day per model (measured from the 429 quota details; resets at midnight Pacific = 12:00 Baku). That covers about 5 customer turns per model per day, so it is an emergency fallback, not a demo runtime. Fallback order: 3.6-flash, 3-flash-preview, 3.5-flash-lite, 2.5-flash (3.5-flash shares the 3.6-flash quota).
- 2026-11-09 A model whose daily quota is exhausted is skipped until its retry time instead of being retried on every turn.
- 2026-11-09 After the customer confirms, the tool result says plainly that the action was executed and verified; a stale "nothing executed" note made one model ask for confirmation again.
- 2026-11-09 Production launcher registers tsx in-process (`node --import tsx`), one process per service: ~300 MB in total, which fits Railway's Free plan.
- 2026-11-09 Hosting: Railway Free plan, project `general-automation-system`, one container. The Cloudflare tunnel stays as backup.
- 2026-11-09 Server speech-to-text follows the team's bake-off: ElevenLabs Scribe v2 with the 22 fixed domain terms first, Groq Whisper large-v3 with the same terms as fallback, 2.5 s deadline each. It runs in the agent service; the browser records one utterance with MediaRecorder and sends it. Without keys the app keeps using browser speech.
- 2026-11-09 A transcript goes in as an ordinary voice turn, so it is shown on both screens and passes the same ingress tokenizer and guards. The STT trace keeps provider, timing and size only, never audio or text.
- 2026-11-09 Free model APIs offered by the team were measured and not adopted for the agent: NVIDIA API catalog (DeepSeek V4.1 Flash, GLM-5.3 Flash) took 66-78 s for a one-word reply; Z.ai glm-4.7-flash took 78 s; Groq's free tier allows 8,000 tokens per minute, cached tokens included, while one agent call is about 4,300 tokens, so it stalls after two calls. The Groq key is used for the speech-to-text fallback, where its limits are separate.
- 2026-11-09 Running the agent on Claude or ChatGPT consumer subscriptions through a self-built bridge was rejected: Anthropic's Agent SDK documentation does not allow third parties to use claude.ai login or subscription rate limits in their products, and an account ban during judging would end the demo.
- 2026-11-09 An OpenAI-compatible model adapter (`AGENT_PROVIDER=mistral | groq | openai-compat`) joins the Anthropic and Gemini ones, so a provider can be swapped with an environment variable. Runtime messages that follow a tool result are folded into that tool message, because strict providers reject a system or user message there. Verified end to end on one dev scenario through Groq gpt-oss-120b (passed; 45 s, all of it rate-limit waiting).
- 2026-11-09 The Anthropic adapter takes an optional base URL and Bearer token from the environment, so model access provided by the event through a gateway needs no code change. The server-side fallback beta can be switched off (`AGENT_FALLBACK=0`) for gateways that do not pass beta parameters.
- 2026-11-09 The backup video is recorded by a headless browser that drives the phone page and approves the bank screens like a customer, while the projector view is filmed. It is the same live system, recorded, not a mock-up.
- 2026-11-09 Runtime model access comes from the event's gateway (Anthropic Messages format, Opus 5.5 and Sonnet 5.5 available). The gateway's account rejects large strict-tool grammars and spends about 10 s per rejection, so strict tool schemas are off there (`AGENT_MAX_STRICT_TOOLS=0`); the agent guard and the Bridge validate every argument anyway (I4). The adapter also adapts by itself to the gateway's own cache breakpoints and to models that reject between-tools thinking.
- 2026-11-09 If the gateway becomes unreachable, the agent switches to Gemini for 60 s and then retries (`MODEL_FALLBACK=gemini`). Guards, Bridge and confirmation do not depend on the model.
- 2026-11-09 Runtime model is Claude Opus 5.5 with adaptive thinking and medium effort. On the dev set through the event gateway it passed 43/43 (turn p50 6.9 s, p95 13.6 s); Sonnet 5.5 passed 40/43, asking needlessly which card "my debit card" meant, which broke the demo chain. Effort stays medium for holdout 2 so the reported numbers match the deployed configuration.
- 2026-11-09 Standing orders take a start from the customer's words as a weekday, a day of the month and an optional month, never as a date the model computes. The core bank resolves the first payment in Baku time (tomorrow at the earliest, one year at the latest) and the bank screen shows it in words, so the customer checks it before approving.
- 2026-11-09 Holdout 2 was completed from the commit it started on (a separate worktree), after the gateway came back, while fixes went to main; this keeps all 560 runs on the same code.
- 2026-11-09 Spoken replies use ElevenLabs (voice "Sarah", model eleven_v4_turbo, falling back to eleven_turbo_v2_5, then to the browser's own voice). Only an answer already in the session transcript can be spoken, requested by its id, with a per-session rate and character cap, so the speech quota cannot be spent from outside. The phone streams the audio through one element unlocked by the customer's tap. The text sent for speech is the answer already on screen; audio is not stored.
- 2026-11-09 Opus fast mode (speed "fast", beta) is supported behind AGENT_SPEED=fast; whether to use it is decided by measurement.
